# Not Applicable

Some evaluation/design-review categories don't fit this project. Each
entry below is marked N/A with a one-line reason grounded in what the
codebase actually does (or deliberately doesn't do) — see
[`docs/DESIGN_REVIEW.md`](DESIGN_REVIEW.md) and
[`docs/ARCHITECTURE.md`](ARCHITECTURE.md) for the fuller picture behind
each.

| Category | Status | Why N/A |
|---|---|---|
| GPU utilization | N/A | Generation runs against the hosted Gemini API (`app/services/gemini_client.py`); the only local model is the small CPU-friendly `all-MiniLM-L6-v2` embedder (`embedding_service.py`), and `backend/Dockerfile` installs the CPU-only torch wheel specifically because no GPU is used or provisioned anywhere in this stack. |
| Agent handoff accuracy | N/A | Single-agent design — one `ChatService` dispatching to three tools (retrieval, summarization, web search), not multiple cooperating agents — so there's no handoff to measure. Web search is a hand-coded score-threshold decision, not an LLM-reasoned handoff to a second agent. See `docs/ARCHITECTURE.md`'s "Framework choice" section for why. |
| Weather / SQL / email / GitHub / vision / speech tools | N/A | Out of scope for a document-QA product. The tool surface is retrieval and summarization over uploaded PDFs, plus a narrow web-search fallback for when retrieval alone doesn't confidently answer the question (`retrieval_service.py`, `summarization_service.py`, `web_search_service.py`) — not a general tool-use surface. Note: PDF text extraction (`document_service.py`) reads PyMuPDF's embedded/selectable text first and falls back to OCR (pytesseract/tesseract) only for pages with no text layer at all — see the README's Features section and Known Limitations for what that fallback does and doesn't cover. |
| Encryption at rest | Resolved as of the AWS migration — see `docs/CHECKLIST.md` §13 | EFS (uploads/vector_store/feedback), SSM `SecureString` (secrets), and S3 default SSE (frontend build) are all encrypted at rest, declared explicitly in `infra/efs.tf`/`infra/ssm.tf`/`infra/s3_frontend.tf` rather than relying on an implicit platform guarantee. Application-level/field-level encryption and customer-managed keys remain future work — this entry covered infrastructure-level encryption specifically. |
| JWT / RBAC | N/A (future work) | Auth is a small keys table (`app/core/auth.py`, `Settings.api_key_table`): a JSON map of client_name -> sha256_hash loaded from `API_KEYS` (or a single fallback `API_KEY` for backward compatibility). Clients send their key in `X-API-Key`; on success, `request.state.client_name` is set for audit logging. When `DATABASE_URL` is configured, keys are also mirrored into a Postgres `api_keys` table and each client resolves to a `tenant` (`app/services/tenant_service.py`) for scoping documents/sessions — still per-client, not per-user. No JWT, tokens, or roles exist — not because they're "planned later" but because this project's actual scale (a demo with a handful of clients, no individual user accounts) doesn't justify the complexity. If/when multi-user access is needed, that's the point to introduce a real identity provider, not before. |
| Live cloud metrics (Prometheus/Grafana dashboards) | N/A | The backend runs on AWS ECS/Fargate (see `docs/OPERATIONS.md` "Deploying to AWS"), which publishes basic CloudWatch metrics automatically (ECS service CPU/memory, ALB request count/latency/healthy-host-count) — enough to back the autoscaling policy in `infra/autoscaling.tf` — but no Prometheus/Grafana or APM integration exists, and per-task Container Insights is left disabled by default for cost. The closest existing tool is still `backend/eval/metrics_report.py`, a local script that parses JSON logs after the fact; its own docstring calls this out as a stand-in for real observability infrastructure, not a replacement for it. |
| Rate limiting (advanced) | N/A (future work) | Basic per-key in-memory rate limiting (60 req/min sliding window) is now implemented in `app/core/auth.py`. A production-grade token bucket with persistence, distributed enforcement, and configurable tiers remains future work. |
